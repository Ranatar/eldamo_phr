# Quettamin — кузница слова

Quettamin (квенья «кузница слова»; имя сложено из слов Eldamo разных периодов) — инструмент для работы со
словами квенья и синдарина всех концепций Толкина (поздней, средней Qenya/Noldorin и ранней Qenya/Gnomish)
по данным лексикона [Eldamo](https://eldamo.org) Пола Страка. Он показывает формы слова во всех периодах,
восстанавливает их по звуковым законам и строит новые слова. Под ним лежит фонетическая модель:
правила Eldamo, их засвидетельствованные применения к словам, граф переходов между звуками и цепочки
изменений с оценкой по свидетельствам и хронологии. Результат — автономная страница в одном HTML-файле,
обозреватель полного корпуса и данные в JSON.

**Слово в центре.** Найденное слово (поиск по обеим ветвям и всем концепциям) открывается карточкой и
**панорамой периодов**: его форма в каждом периоде обеих ветвей — засвидетельствованная или восстановленная.

**Словотворчество**: соединить два (или три) слова на выбранной стадии истории языка и получить
вероятные формы сложения с правилами, которые к ним привели (Ambar + lindë → amballindë), а также
присоединить суффикс или приставку (cen- + -ima → cénima). Как это
устроено и насколько можно доверять ответам — `docs/word-formation.md`.

**Реконструкция** восстанавливает форму слова для другого периода: более ранней или поздней стадии языка,
другой ветви (когнат квенья ↔ синдарин) или другой концепции Толкина, в том числе форму, которой нет в
Eldamo (lindë → ✶lindē, glindē; ᴹQ. → Q. по связям Eldamo или переэтимологизацией). Описание —
`docs/reconstruction.md`.

- Quettamin: `app/index.html` (после сборки), опубликованная версия — <https://ranatar.github.io/quettamin/>
  (репозиторий <https://github.com/Ranatar/quettamin>, прежнее имя — eldamo_phr).
- Обозреватель корпуса: `app/corpus.html`.
- Данные ветвей: `branches/<ветвь>/data/*.json`, читаемый каталог правил: `branches/<ветвь>/catalog.md`.
- Аудит сборки: `reports/audit.md`; проверка секвенсора и словотворчества: `reports/sequencer.md`;
  проверка реконструкции: `reports/reconstruction.md`.

## Источник

Единственный вход — модель данных Eldamo `eldamo-data.xml`, сжатая в
`source/eldamo-data-0.8.13.xml.xz` (4 МБ). Контрольные суммы XML и исходного релизного архива — в
`source/SOURCE.json`; сборка сверяет их и читает XML строго как UTF-8. Остальной сайт Eldamo не нужен и
не распространяется.

Обновление на новую версию Eldamo:

```
python scripts/import_eldamo_release.py eldamo-X.Y.Z.zip     # или путь к eldamo-data.xml
python scripts/build.py
```

## Сборка

Нужен только Python ≥ 3.8 (подходит последний Python для Windows 7), без сторонних пакетов:

```
python scripts/build.py              # данные, каталоги, экспорт, страницу Quettamin, отчёты и все тесты
python scripts/build.py --no-browser # без браузерного теста
python scripts/build.py --no-tests   # только сборка
python scripts/build.py --full       # пересчитать данные и отчёты, даже если они актуальны
```

Полная сборка: модель — около минуты, ещё несколько минут — проверки для отчётов: секвенсора и
словотворчества (`reports/sequencer.md`: прогон всех дериваций, сложения «без одного», восстановление
праформ) и реконструкции (`reports/reconstruction.md`; случаи считаются параллельно, по числу процессоров,
`QUETTAMIN_JOBS` задаёт число процессов). Данные ветвей и отчёты зависят только от `source/` и
Python-кода в `shared/` (кроме `app.py` и `exports.py`, которые делают страницы, и `parity.py` — векторов для теста): `reports/inputs.json`
хранит отпечаток этих файлов, и если он не изменился, сборка читает готовые данные и пересобирает
только страницы и экспорт — секунды вместо минут. Тесты строят модель из источника сами, так что
устаревшие данные они всё равно поймают; браузерные тесты идут в отдельном процессе параллельно
остальным.
Она детерминирована: на Python 3.8 в локали cp1251 и на Python 3.13 в UTF-8 получаются побайтово
одинаковые файлы (все файлы пишутся в UTF-8 с `\n`, атомарно).

Браузерный тест (`tests/test_browser.py`) необязателен: ему нужен Playwright
(`pip install playwright && python -m playwright install chromium`), и он пропускается, если Playwright
или браузера нет. `ELDAMO_CHROMIUM=/путь/к/chrome` задаёт свой браузер, `ELDAMO_REQUIRE_BROWSER=1`
превращает пропуск в ошибку.

## Командная строка

Те же реконструкция и словотворчество — без браузера, по данным, которые записала сборка (команда
отвечает за секунды). Периоды пишутся «ветвь/концепция/стадия»: `quenya/late/2` — Q., `sindarin/late/3` — S.,
`quenya/middle/2` — ᴹQ., `sindarin/early/1` — G.

```
python scripts/quettamin.py word lindë                                # статьи лексикона
python scripts/quettamin.py reconstruct erinqua --to sindarin/late/3  # форма для другого периода
python scripts/quettamin.py reconstruct ereb --from sindarin/late/3 --to quenya/late/2 --form
python scripts/quettamin.py panorama galadh                           # все периоды сразу
python scripts/quettamin.py compose Ambar lindë                       # сложение
python scripts/quettamin.py compose cen- -ima                         # основа + суффикс
python scripts/quettamin.py affix -ima                                # засвидетельствованные производные
```

Слово можно указать и идентификатором статьи Eldamo. Формы в ответах — в фонетической записи Eldamo.

## Как получаются данные

Конфигурация ветвей — `shared/languages.py`:

| ветвь | поздняя концепция | средняя концепция | ранняя концепция |
|---|---|---|---|
| quenya | ✶ Primitive → AQ. Ancient Quenya → Q. Quenya | ᴹ✶ → ᴹAQ. → ᴹQ. | ᴱ✶ → ᴱQ. Qenya |
| sindarin | ✶ → AT. Ancient Telerin → OS. Old Sindarin → S. Sindarin | ᴹ✶ → ON. Old Noldorin → N. Noldorin | ᴱ✶ → G. Gnomish |

1. **Правила** (`shared/model.py`) — страницы `<word speech="phonetic-rule">` языков ветви: название,
   общая формула (`@from > @rule`), порядок `@order`, связи `<before>`, заметки, подформулы `<rule>`.
   Правила, удалённые Толкином (`mark="-"`), исключаются.
2. **Деривации** — каждый `<deriv>` с шагами `<rule-example>`: последовательность применения правил к
   слову с промежуточными формами, как её приводит Eldamo со ссылкой на источник. Шаг связан с
   подформулой по тройке «язык, from, rule» (две тройки в Eldamo 0.8.13 повторяются на одной странице —
   шаг относится к первой). Подформула получает язык и ступень из собственного `l`. Деривации, отвергнутые
   Толкином, помечаются и не считаются свидетельствами. Праэльфийские шаги общие для обеих ветвей; в справочнике по умолчанию
   показываются слова своей ветви.
3. **Проверка формул** (`shared/interpreter.py`) — каждый шаг проигрывается: формула применяется к
   предыдущей форме, результат сравнивается со следующей. Интерпретатор реализует нотацию из
   `general/phonetic-descriptions.html` Eldamo (классы `V C X S`, долгота, наборы `{…}` с `|`, индексы,
   `ø`, позиции через дефис, применение ко всем позициям сразу) и недокументированные, но используемые
   `C*` и знаки ударения. Неизвестная нотация даёт явный статус `unsupported`, а не тихий «не совпало».
   Соглашения сравнения: две одинаковые краткие гласные равны долгой (`laa` = `lā`), ударение не
   учитывается, при `CCC > CC` выпадает средний согласный, при `-CC > -C` — последний. Шаги с `+`
   (граница морфем) проверить нельзя — в формах граница не записана, они получают `unsupported`.
   Шаги по неизменным подформулам-исключениям и по удалённым правилам в процент не входят.
4. **Граф** (`shared/graph.py`) — рёбра из литеральных подформул (`a > b`, включая исчезновение `a > ø`).
   Ребро сохраняет условие своего правила: общую формулу с классами и исключения — неизменные подформулы
   вида `mb > mb` на странице правила («voiced stops became spirants *except after nasals*»), а также
   условие ударения. Узлы — звуки без знаков ударения и краткости (`ˌau` и `au` — один узел).
   Подформулы с классами и контекстом, а также подформулы языков вне ветви в граф не входят.
5. **Цепочки** — пути из 2–3 рёбер одного периода в хронологическом порядке: следующая языковая ступень,
   либо внутри языка порядок Eldamo (`order`, `<before>`; меньший `order` — более раннее правило, это
   подтверждают все 413 связей `<before>` с известным порядком). Пути, которым хронология Eldamo
   противоречит, отбрасываются (их число — в отчёте). Свидетель — шаг деривации, который формула
   воспроизводит и который меняет форму. Оценки:

   | | значение |
   |---|---|
   | **A** | шаги применены в этом порядке в одной засвидетельствованной деривации |
   | **B** | у каждого шага есть воспроизведённые засвидетельствованные примеры, порядок подтверждён |
   | **C** | у каждого шага есть такие примеры, но порядок части шагов не установлен |
   | **D** | у какого-то шага нет воспроизведённых засвидетельствованных примеров |

6. **Секвенсор** (`shared/sequencer.py`) — прогон формы через все правила ветви в хронологическом порядке.
   Порядок правил без `order` (все праэльфийские) выводится топологической сортировкой из дериваций и
   `<before>`. Необязательные правила («often», «sometimes») ветвятся; применяет ли их основное чтение,
   решает их доля в засвидетельствованных деривациях (`data/calibration.json`). Ударение вычисляется
   (`shared/stress.py`): начальное в праэльфийском и древних стадиях, «латинское» в квенья и синдарине.
7. **Лексикон** (`shared/lexicon.py`) — статьи ветви: омонимы по отдельности, основы, элементы сложений,
   корни, праформы и формы на стадиях из дериваций (`data/lexicon.json`).
8. **Сложения и аффиксы** (`shared/compound.py`, `junctions.py`, `affixes.py`, `morphophonology.py`,
   `backform.py`) — соединение
   элементов на стадии и прогон, таблица стыков по засвидетельствованным сложениям
   (`data/junctions.json`), формы и стыки суффиксов и приставок по производным словам
   (`data/affixes.json`), правила §6.1 учебника Страка, мягкая мутация синдарина, восстановление
   праформы для слов без деривации.

## Что умеет Quettamin

- поиск слова по форме и значению сразу в квенья и синдарине всех концепций; неологизмы — по переключателю;
  недавние слова запоминаются в браузере;
- карточка слова: язык, значение, основа, корень, праформа, связи Eldamo (объединено с, заменено на,
  когнат) со ссылками, переход к его деривациям;
- корни: из дериваций Eldamo, иначе через составляющие, то же слово другой концепции, заменённое слово и
  когнаты (правила сверены с neo-roots); дерево происхождения в карточке — от слова через составляющие и
  промежуточные формы к корням, с записанными промежуточными формами; для праформы без корня — кандидаты
  из корней Eldamo той же концепции (гипотеза);
- граф происхождения (`graph.html`, адрес `#n-<страница>`): окрестность слова или корня — дерево до корней и
  производные, разворачиваемые двойным щелчком, — и «Карта истоков»; по образцу графа neo-roots, работает без сети;
- указатель корней (вкладка «Корни», адрес `#r=<страница>`): карточка корня — слияния, под каким корнем
  записан, из какого выводится, предупреждения Eldamo (заменён, отвергнут, ранний…), слова обеих ветвей от
  него; поиск, рекомендованные корни и рекомендованные без производных — материал для новых слов;
- панорама периодов: корни и форма слова в каждом периоде обеих ветвей (праформа, промежуточные стадии, язык) с
  пометкой «засвидетельствовано / связь Eldamo / восстановлено / неологизм / нетипично для языка»;
  щелчок по клетке открывает реконструкцию;
- реконструкция: варианты с весом, маршрутом, пометками и правилами по стадиям; любой вариант можно сделать
  текущим словом;
- словотворчество: выбранное слово — первый элемент; второй (и третий) — слово, суффикс или приставка; стадия
  образования, ранжированные варианты с источником формы, изменениями на стыке, правилами и
  засвидетельствованными аналогами; взятый в работу вариант помнит свои элементы — его корни, праформа и
  реконструкция идут от их этимологии;
- фонетический справочник в трёх свёрнутых разделах со своей ветвью и концепцией и кнопкой «развернуть всё»:
  звуки (сетка МФА), пути между ними с учётом хронологии и фильтрами, деревья развития и происхождения,
  правила звука и отдельного правила (формула, подформулы, засвидетельствованные примеры); атлас цепочек
  с оценками A–D; деривации Eldamo с проверкой каждого шага и кнопкой «открыть слово». Правило в любом
  ответе открывается в справочнике;
- адрес страницы хранит состояние (`#w=403686503&dst=sindarin/late/3`, `#ref=paths&b=quenya&from=b&to=v`),
  кнопка «назад» работает; прежние адреса атласа (`#quenya?from=b&to=v`) открывают справочник;
- движок словотворчества и реконструкции — порт Python-кода на JavaScript (`app/wordform.js`), совпадение
  ответов проверяется браузерным тестом;
- интерфейс на русском и английском: кнопка в шапке, `#lang=en` в адресе; выбор запоминается, без выбора
  язык берётся из браузера. Переводится только интерфейс: формы, значения, названия правил и языков —
  данные Eldamo, они остаются как есть. Все тексты — в каталоге `app/messages.json` (ключ → `ru`, `en`;
  числа — с формами множественного числа);
- светлая и тёмная тема, работа без сети, мобильная вёрстка.

```
source/            eldamo-data-*.xml.xz и SOURCE.json — единственный вход
shared/            source, languages, model, interpreter, formula, graph, pipeline,
                   ipa, catalog, exports, app, report, io;
                   словотворчество: stress, sequencer, lexicon, orthography, junctions,
                   affixes, morphophonology, backform, compound, parity, roots;
                   реконструкция между периодами: reconstruct
scripts/build.py   полная сборка и тесты
scripts/quettamin.py   командная строка: word, reconstruct, panorama, compose, affix
scripts/import_eldamo_release.py   импорт новой версии Eldamo
app/               template.html, styles.css, messages.json и i18n.js (тексты интерфейса на двух языках);
                   router.js (адрес), wordform.js (движок), word_ui.js (поиск,
                   карточка, панорама), wordform_ui.js, reconstruct_ui.js (инструменты), runtime.js (справочник),
                   corpus_template.html → index.html, corpus.html
branches/<ветвь>/  data/{phonemes,rules,pairs,derivations,edges,chains,lexicon,junctions,
                   affixes,calibration,stages,summary}.json, catalog.md
exports/           canonical.json (всё одним файлом), atlas.graphml (граф для Gephi/yEd)
reports/           audit.md, audit.json — охват, проверка шагов, невоспроизведённые шаги;
                   sequencer.md, sequencer.json — прогон дериваций, сложения, восстановление праформ;
                   reconstruction.md, reconstruction.json — реконструкция между периодами
tests/             поведение интерпретатора, инварианты против XML, граф, выходные файлы, браузер
docs/              словотворчество (word-formation.md) и его план (word-formation-plan.md),
                   как Eldamo читает свою базу (eldamo-xquery.md),
                   реконструкция между периодами (reconstruction.md) и её план
                   (period-reconstruction-plan.md), план переделки интерфейса (ui-redesign-plan.md),
                   переход с HTML-конвейера (MIGRATION.md), наследие прежних этапов (legacy/),
                   прежние README и отчёты (history/)
```

Сгенерированные HTML и `exports/` в git не хранятся: их собирает `scripts/build.py`, а для GitHub Pages —
workflow `.github/workflows/pages.yml`. Данные ветвей, каталоги и отчёт хранятся, чтобы изменения между
версиями Eldamo и кода были видны в диффах.

## Ограничения

- Граф связывает только литеральные подформулы. Правила с классами (`V{ptk} > V{bdg}`) применимы к
  словам, но не дают рёбер «звук → звук»; они видны в правилах звука и в деривациях.
- Цепочка с оценкой A засвидетельствована в слове, но связность сегментов между шагами не проверяется:
  засвидетельствовано, что оба правила применены к слову в этом порядке.
- При проверке отдельных шагов знаки ударения в формулах игнорируются (ударение в формах не записано),
  поэтому такие правила могут применяться шире, чем у Страка. Секвенсор ударение вычисляет.
- Ответы словотворчества — предсказания модели, а не формы Толкина; их точность на засвидетельствованных
  данных — в `reports/sequencer.md`, ограничения — в `docs/word-formation.md`. То же для реконструкции:
  `reports/reconstruction.md` и `docs/reconstruction.md`.
- Около 6% засвидетельствованных шагов формулы не воспроизводят: в Eldamo встречаются шаги, где в одной
  записи совмещено несколько изменений, повторы формы, позиционные правила внутри сложных слов, а в
  квенийских формах иногда пишется `y` вместо `j`. Полный список — `reports/audit.json`, разбор по
  правилам — `reports/audit.md`.
- Порядок Eldamo (`order`) есть у 211 из 251 правил квенья и у 263 из 303 синдарина; где его нет,
  переход внутри одной ступени считается неустановленным (оценка C).
