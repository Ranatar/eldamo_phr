# Контекстное применение правил Eldamo: проверка 101 цепочки

**Материал:** локальный архив Eldamo 0.8.13, таблицы 101 цепочки и примеры правил, сохранённые на предыдущих этапах.

## Что действительно выполнено

- Реализован и протестирован консервативный интерпретатор **базовых** фонетических замен в полных словоформах: буквенные комбинации, `V` и `C`, удаление `ø`, позиции начала/конца слова через `-`.
- Проверены 101 ранее составленная цепочка и 140 строк словоформ (если число звуковых ступеней совпадает с числом словоформ).
- **Не реализованы** внутри настоящего прототипа: группы `{...}`, индексы метатезы, просодические переменные `S`, продуктивная обработка `V̄`, `V̆`, ударений и других сложных конструкций. Их нельзя считать отвергнутыми.
- Список 101 изначально получен из сравнительно простых формул. Поэтому полное распознавание его 214 звуковых шагов **не означает**, что весь синтаксис Eldamo интерпретирован.

## Результаты

- В исходном наборе: 101 цепочка, 214 формальных шагов.
- Непрерывные последовательности конкретных словоформ воспроизведены хотя бы на одном примере для **24 цепочек**.
- Всего успешно воспроизведено 275 из 280 проверок переходов по примерам (включая повторяющиеся свидетельства).
- **76** цепочек не имеют непрерывного примера, пригодного для буквальной проверки на всём пути; это не значит, что они запрещены.
- **1** цепочка имеет пример, в котором буквальное преобразование не воспроизводит приведённый промежуточный шаг.

## Пять ранее неопределённых цепочек с воспроизводимыми примерами

Это новые **технические свидетельства применимости строк**, но не разрешение проблем периода концепции или языка.

- **#16:** `bd → pt → ɸt` — `labdē → laptē → laɸtē`.
- **#78:** `kʰ → x → h` — `nakʰam- → naxam- → naham-`.

## Аномалии и ограничения

- Цепочка **#39** (`sd → zd → st`): в одном использованном примере второй переход записан как `nizdo → nizdo`. Это не воспроизводит `zd → st` и требует ручного разбора привязки примера к правилу.
- Отдельные строки из цепочек #29 и #78 дают несовпадения, хотя другие примеры #29 воспроизводят полную цепочку. Нельзя ни отвергать всё правило, ни считать каждую строку подтверждением.
- Интерпретатор работает с символьными строками, не переводя произвольную орфографию в IPA. Запись конкретного слова может не совпадать с фонетической транскрипцией в формуле.
- Не проверены одновременная применимость всех окружений в рамках каждой исторической ступени, относительная хронология, диалект, принадлежность редакции и происхождение слова. Переход от D/U к B/A по одному совпадению запрещён.
- Правила с переменными и контекстами, исключённые из первоначальной генерации 101 пути, остаются задачей для отдельного алгоритма поиска новых путей.

## Следующий технический рубеж

Нужно перейти от простого применения пары строк к формальному описанию правила `{pattern, replacements, environment, language_stage, conceptual_period, dialect, precedence}`. Проверять конкурирующие правила по порядку, затем генерировать новые цепочки из полной базы, включая пока неразбираемые формулы. Составлять отдельные доказательства на уровне слова и на уровне закона.
