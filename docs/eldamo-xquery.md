# Как Eldamo читает свою XML-базу

Сайт Eldamo строится из `eldamo-data.xml` запросами XQuery (`src/main/webapp/config/query-configs/*.xq`
в репозитории [pfstrack/eldamo](https://github.com/pfstrack/eldamo), версия 0.8.13) и несколькими функциями
на Java (`src/main/java/xdb/dom/CustomFunctions.java`). Ключи поиска объявлены в
`config/model-configs/model-config.xml`. Ниже собрано, как генератор понимает данные, и что из этого следует
для Quettamin. Источники разбора: `common.xq`, `word-page.xq`, `misordered-rules.xq`, `phonetic-index.xq`,
`model-config.xml`, `CustomFunctions.java`.

## Наследование и поиск

| что | как у Eldamo | в Quettamin |
|---|---|---|
| язык | `c:get-lang`: ближайший предок с `@l` — у `<element>`, `<cognate>`, `<deriv>` без `l` язык статьи | так же |
| часть речи | `c:get-speech`: ближайший предок с `@speech` | у всех статей 0.8.13 свой `@speech` |
| слово по ссылке | `c:get-word`: статьи с той же формой `@v`; при `@l` — этого языка, иначе единственная статья с такой формой, иначе статья языка, унаследованного ссылкой | `Words.get_word` |
| ссылка по месту источника | `c:get-ref`: единственная `<ref>` с этим `@source`; если таких несколько — ничего | `Words.ref` |
| «действительные» ссылки | `$word/ref[c:get-ref(.)]` — с уникальным `@source` | в 0.8.13 повторяющихся `@source` нет |
| отвергнутое Толкином | `-` в любом месте `@mark` (`-`, `†-`, `#-`) | так же (раньше — только `-` в начале) |
| удалённый раздел | `|` в `@mark`: зачёркнуто, но не отвергнуто | не исключается |
| значение | `c:get-gloss`: `@gloss`; иначе значение единственной вложенной статьи; иначе общее значение ссылок без `<inflect>` и `<correction>` | так же |

## Связи, записанные внутри ссылок

Многое Eldamo записывает не в статье, а внутри `<ref>`: связь относится к конкретному месту источника.
Такие связи обычно без языка, зато с `@source` — местом источника, где названо связанное слово; его
находят через `c:get-ref`.

| связь | в статье | внутри ссылок | как читает Quettamin |
|---|---|---|---|
| `<cognate>` | 1479 | 5021 | транзитивно, как раздел Cognates (ниже) |
| `<element>` | — | 18706, у всех `@source` | по `@source`, затем по форме |
| `<deriv>` | — | 12817 с `@source` | форма `@v` как записанная праформа |
| `<related>` | есть | есть | не используется |

**Когнаты.** Раздел Cognates страницы (`allReferenceCognates`, `allWordCognates`) — это все слова,
связанные с данным цепочкой `<cognate>`: через ссылки (`<cognate source>` ведёт к ссылке другого слова,
и обратно — к ссылкам, которые указывают сюда) и через саму статью (`<cognate l v>`). Замыкание
транзитивное; слова того же языка исключаются. Quettamin строит то же замыкание: у слов квенья 751
синдаринский когнат, у синдаринских — 738 квенийских.

## Формы слова: словоформы и варианты

`word-page.xq` делит ссылки статьи на три вида:

- **словоформы** — ссылка с `<inflect>` (раздел Inflections): множественное Edain у Adan, аорист farále
  «ты охотишься» у fara-;
- **варианты** — ссылка без `<inflect>` и `<correction>` с другой формой (раздел Variations): Altariellë у
  Altáriel;
- **исправления** — ссылка с `<correction>` или `<change>` (раздел Changes).

Деривация словоформы не говорит о праформе самого слова, деривация варианта говорит. Поэтому Quettamin
отбрасывает при поиске праформы только деривации и записанные праформы ссылок с `<inflect>` (они
перечислены в `other_forms` статьи): 202 статьи квенья и 268 синдарина. В версии 3.1 отбрасывались все
ссылки с другой формой, в том числе варианты, — это было лишним.

## Деривации и фонетические правила

- `<deriv>` внутри ссылки: `@v` — праформа в записи источника, `@source` — её ссылка (обычно в статье
  праэльфийского слова или корня), `@i1`, `@i2`, `@i3` — записанные промежуточные формы (696 раз;
  Quettamin их не использует, язык у них не указан).
- `<rule-start stage>` и `<rule-example l rule from stage>` — шаги фонетической деривации; правило шага
  находится по ключу `rule-to` = `l:rule:from` среди `<rule>` фонетических правил. Quettamin делает то же.
- `misordered-rules.xq` — отчёт самопроверки Eldamo: правила, чей `<before>` противоречит `@order`, и
  статьи, где шаги одной деривации одного языка идут против `@order`. Для 0.8.13 второй список пуст (проверено
  тем же запросом на Python): порядок правил Eldamo согласован со всеми деривациями. Расхождения обратного
  прогона Quettamin возникают не из-за порядка правил, а из-за формул и правил без `@order`
  (праэльфийские, ᴹ✶), чей порядок выводится по деривациям.

## Что ещё может пригодиться

- `@ngloss` — значение для неоэльдарина (Quettamin берёт его, если нет `@gloss`).
- `@orthography`, `@tengwar`, `@stem` статьи; `<class form variant>` — класс склонения или спряжения.
- `c:normalize-spelling` — запись квенья для показа: q → qu, k → c, ks → x, конечное -e → -ë.
- Неоэльдарин объединяет языки в группы: NQ. = nq, q, mq, eq; NS. = ns, s, n, en, g; N✶ = np, p, mp, ep;
  статья с `<combine>` показывается на странице объединённого слова.
